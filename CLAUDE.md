# CLAUDE.md — Vivra

Read `docs/PLAN.md` before any work. It holds the architecture, the phases,
and the definition of done for each phase.

## Current phase

**Phase 0 (foundations)** is done (CI green on `main`). The owner still needs to
do the device run, but it doesn't gate anything. **Phase 1 needs the owner's
explicit approval before it starts.**

## Hard rules

- **No network calls.** No `URLSession`, no `Network` framework, no third-party
  SDKs. `scripts/check-guards.sh` enforces this in CI.
- **No health data in logs.** Log only through `VivraLogging.Log`, whose
  messages are `StaticString`s. No `print`, `NSLog` or `os.Logger` elsewhere.
- **The LLM never produces numbers.** All statistics are computed in Swift and
  the model only words them (PLAN §6).
- **Not medical advice.** Use observational, non-causal and non-judgemental
  language (see `docs/STYLE_GUIDE.md` once it exists).
- **Injected clocks, calendars, time zones and locales** in core logic. No
  `Date()` or `Calendar.current` in `Packages/VivraCore`.
- **Ask before adding a dependency.** Approved so far: GRDB.swift (vendored with
  SQLCipher in `Vendor/GRDB`), SQLCipher.swift (pinned exactly), and XcodeGen
  (a dev tool only).
- **Never edit `Vendor/GRDB/GRDB` or `Vendor/GRDB/Sources` by hand.** Use
  `scripts/vendor-grdb.sh`.
- **Never edit a shipped migration.** Always add a new one.

## Conventions

- Swift 6 language mode with strict concurrency. iOS 26 minimum.
- Format with `swift format` using the repo's `.swift-format`.
- Use Swift Testing (`import Testing`) for tests.
- Commits follow conventional commits (`feat:`, `fix:`, `chore:`, `docs:`).
- The `.xcodeproj` is generated by XcodeGen from `project.yml`. Never commit it.
- This cloud environment has no Xcode. Verify Apple-only code through CI
  (GitHub Actions `macos-26`). A Linux Swift toolchain can build and test
  `Packages/VivraCore` only.
